۲) لایه‌های معماری

Presentation

Next.js + React + TypeScript + Tailwind + Lightweight Charts. ترمینال یک محیط کاری است، نه داشبورد اسکرولی.

API / Application

FastAPI، use-case orchestration، lifecycle، policy enforcement، request validation و APIهای typed.

Domain

قراردادهای مستقل از vendor: MarketData، Indicator، Analysis، Risk، Evidence، Intelligence، Governance و Outcome.

Infrastructure

PostgreSQL، NATS JetStream، Redis، Arrow/Parquet/DuckDB و adapterهای OSS/provider.

Workers

کارهای asynchronous برای data ingestion، research، replay، evaluation، learning و health recovery.

Governance

approval queue، provenance، audit، policy، rollback، secret boundaries و قابلیت توقف اضطراری.

۵) چرخه کامل MIOS

MIOS باید از outcome واقعی یاد بگیرد، نه از صرفاً متن تولیدشده توسط مدل. هر تغییر باید evidence، validation، owner/approval، نسخه، benchmark و rollback path داشته باشد.

۶) سلامت و امنیت

ورودی

schema validation، payload limits، rate limits، CORS، authentication و authorization.

Research

SSRF protection، allow/deny policy، redirect controls، content-size/time limits و provenance.

Secrets

عدم قرار دادن secret در source/log/evidence؛ secret reference به جای secret value.

Supply Chain

version pinning، advisory scan، license review، optional dependencies و compatibility gate.

Runtime

liveness/readiness، dependency health، timeout، circuit breaker، fallback و graceful degradation.

Governance

audit، immutable evidence، approval، canary، rollback و kill switch.

۱۰) قواعد غیرقابل مذاکره معماری

  1. Contract-first: domain هرگز به vendor API وابسته نمی‌شود.
  2. OSS-first: قبل از نوشتن implementation جدید، OSS بالغ بررسی و benchmark می‌شود.
  3. No fake data: timestamp، price، provider health و evidence هرگز جعل نمی‌شوند.
  4. One analysis result: همه UIها از Unified Analysis استفاده می‌کنند.
  5. Human governance: self-development پرریسک بدون approval وارد production نمی‌شود.
  6. Deterministic evaluation: تغییرات تحلیلی قبل از promotion با replay/backtest/benchmark بررسی می‌شوند.
  7. Observable by default: هر مسیر مهم باید health، metric، trace و audit داشته باشد.
  8. Graceful degradation: نبود یک provider نباید کل سیستم را از کار بیندازد.
  9. Rollback first: هر promotion بدون مسیر برگشت ناقص محسوب می‌شود.
  10. Minimal coupling: هیچ موتور OSS صرفاً برای «داشتن نام آن» اضافه نمی‌شود.
